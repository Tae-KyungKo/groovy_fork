# 원본 레포 통합 시 주의점

> 이 저장소(`groovy_fork`)는 로컬 개발/MSA 전환 작업용이다. 운영 서버에 실제로 배포되는
> compose/env 파일은 이 저장소가 아니라 운영 서버에서 직접 작성·관리하고 있어, 이 저장소의
> 로컬 개발 편의를 위한 설정 중 일부는 **원본 Groovy 레포로 다시 통합해 실제 운영에 반영할 때
> 반드시 그대로 가져가면 안 되는 것들**이 있다. 통합 작업 시 이 문서를 체크리스트로 쓴다.

## 1. 운영용 Docker Compose 파일이 이 저장소엔 없다

로컬 개발에는 `docker-compose.local.yml`(전부 노출)과 `docker-compose.example.yml`(온보딩용
사본)만 있고, 운영 배포용 compose 파일은 운영 서버에서 별도로 관리한다(`.github/workflows/docker-build-push-frontend.yml`의 배포 잡도 이 저장소를 체크아웃하지 않고 운영 서버의
`/home/shared` 아래 파일을 그대로 쓴다).

원본 레포로 통합하면서 운영용 compose를 다시 만들거나 갱신할 때 아래 설계 목표를 지킬 것
(`docs/Groovy_MSA_구조와실행.md` 4장 "prod 노출" 열 참고):

- 호스트에 직접 노출하는 포트는 `api-gateway`(8080)와 `grafana`(3000)뿐이어야 한다. 나머지
  서비스(identity/study/content/calendar/notification-service, mysql/redis/kafka,
  tempo/loki/alloy)는 내부 네트워크(`groovy-net`)에서 서비스명으로만 접근 가능해야 한다.
- 비밀값은 로컬처럼 기본값을 두지 말고 `${VAR:?...must be set}` 문법으로 `.env` 미설정 시
  기동이 실패하도록 강제한다.
- `restart: unless-stopped`(또는 그에 준하는 재시작 정책)를 명시한다.

## 2. Grafana 익명 Admin 접근 — 운영 통합 전 반드시 제거

`docker-compose.local.yml`/`docker-compose.example.yml`에 다음 설정이 있다.

```yaml
GF_AUTH_ANONYMOUS_ENABLED: "true"
GF_AUTH_ANONYMOUS_ORG_ROLE: Admin
```

이는 **로컬 개발 중 로그인 없이 대시보드를 바로 확인하기 위한 편의 설정**이며, `grafana` 포트가
호스트에 노출되는 유일한 관측성 컨테이너라는 점과 결합하면 인증 없이 Grafana Admin 권한(대시보드
변경, 데이터소스 프록시 쿼리 등)을 획득할 수 있는 상태다. 로컬 전용으로는 위험이 낮지만,
**원본 레포로 통합해 운영에 반영할 때는 반드시**:

- `GF_AUTH_ANONYMOUS_ENABLED`를 `false`로 끄거나, 최소한 `GF_AUTH_ANONYMOUS_ORG_ROLE`을
  `Viewer`로 낮출 것.
- `GF_SECURITY_ADMIN_USER`/`GF_SECURITY_ADMIN_PASSWORD`로 실제 관리자 계정을 발급할 것
  (현재 두 값 모두 compose에 명시돼 있지 않아 Grafana 기본 계정 `admin`/`admin`이 그대로 남는다 —
  이것도 함께 바꿔야 한다).
- 위 두 가지를 적용하기 전까지는 `GRAFANA_PORT`를 호스트에 직접 노출하지 말 것(nginx 뒤에 두고
  별도 인증/접근 제어를 추가하는 방안도 함께 검토).

## 3. (참고) nginx.conf가 아직 레거시 모놀리식 hostname을 가리킴

이번 통합 대상은 아니지만 같은 카테고리라 기록해둔다. `nginx/nginx.conf`는 운영 배포용 리버스
프록시 설정인데 `proxy_pass http://backend:8080`처럼 **MSA 전환 이전(레거시 모놀리식 컨테이너명
`backend`)** 값을 그대로 갖고 있다. 현재 MSA 구조의 단일 진입점은 `api-gateway`(8080)이므로,
운영 통합 시 이 값도 함께 갱신해야 한다.
