# 02. 원본 레포 통합 시 주의점 문서화

**날짜**: 2026-08-19
**분석 결과 원문 항목**: 종합 분석 🔴 2번(Grafana 익명 Admin 노출)

## 배경

`docker-compose.local.yml`/`docker-compose.example.yml`에 `GF_AUTH_ANONYMOUS_ENABLED: "true"`
+ `GF_AUTH_ANONYMOUS_ORG_ROLE: Admin`이 설정되어 있어, 로그인 없이 Grafana Admin 권한을 얻을
수 있다. 로컬 개발 편의를 위한 의도적 설정이지만, 이대로 원본 Groovy 레포에 통합해 운영에
반영하면 인증 없이 대시보드 변경/데이터소스 프록시 쿼리가 가능해지는 실제 취약점이 된다.

사용자 결정: 지금 당장 고치지 않고, **원본 레포로 통합하는 시점에** 반영한다.

## 조치

`docs/원본 레포 통합 시 주의점.md`를 새로 작성해 체크리스트로 남겼다.

1. 운영용 compose 파일이 이 저장소엔 없다는 점, 통합 시 새로 만들 때 지켜야 할 설계 목표
   (호스트 노출은 `api-gateway`+`grafana`만, `${VAR:?...}` 필수값 강제, restart 정책).
2. Grafana 익명 Admin을 반드시 끄고 실제 관리자 계정(`GF_SECURITY_ADMIN_USER/PASSWORD`,
   확인 결과 현재 미설정이라 Grafana 기본 계정 `admin`/`admin`이 그대로 노출됨)을 발급할 것.
3. (덤으로 발견) `nginx/nginx.conf`가 아직 레거시 모놀리식 hostname(`http://backend:8080`)을
   가리키고 있어 통합 시 `api-gateway`로 갱신 필요 — 오늘 처리 대상은 아니라 참고용으로만 기록.

## 검증

`GF_SECURITY_ADMIN_USER`/`PASSWORD`가 실제로 미설정임을 grep으로 확인, `nginx.conf`의
`proxy_pass http://backend:8080`도 실제 확인.
